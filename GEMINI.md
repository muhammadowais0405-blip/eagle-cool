# Gemini Context: Eagle Media Manager

This document provides essential context for Gemini to understand the architecture, development workflow, and conventions of the Eagle Media Manager project.

## Project Overview

Eagle Media Manager is a local-first media library manager inspired by Eagle.cool. It allows users to organize images and videos into libraries with tagging, folders, and metadata management, all stored locally on the user's machine.

### Tech Stack
- **Framework**: Electron (Main & Renderer architecture)
- **Frontend**: Vue 3 with Composition API
- **Build Tool**: Vite with `vite-plugin-electron`
- **Language**: TypeScript
- **Media Processing**: `sharp` (images), `fluent-ffmpeg` (videos)
- **Styling**: Vanilla CSS

---

## Directory Structure

- `src/main/`: Electron main process source code.
  - `main.ts`: Entry point, IPC handlers, and `LibraryManager` class.
  - `ThumbnailCache.ts`: Management of generated thumbnails.
  - `types.ts`: Common TypeScript interfaces for the entire project.
- `src/preload/`: Electron preload script (IPC bridge).
- `src/renderer/`: Vue 3 frontend source code.
  - `src/App.vue`: Root component.
  - `src/components/`: Reusable UI components.
  - `src/composables/`: Vue composition functions for library and import logic.
  - `src/styles/`: Global and component-specific styles.
- `dist/`: Compiled assets (generated by Vite).
- `release/`: Packaged application binaries (generated by `electron-builder`).

## Library Architecture

Libraries are stored as folders on the disk with the following structure:

```text
YourLibraryFolder/
├── library.json            # Manifest: library name, folders, tags, settings
├── index.json              # Fast-path cached index of all items
└── images/                 # Core storage
    └── [id].info/          # Per-item directory
        ├── content.[ext]   # Original media file
        ├── metadata.json   # Item-specific metadata (tags, notes, dimensions)
        ├── thumbnail.webp  # Generated 400px thumbnail
        └── preview.webp    # (Optional) High-res preview for large images
```

### Data Management
- **IndexStore**: Manages the `index.json` file for fast searching and loading.
- **LibraryManager**: Orchestrates imports, searches, and metadata updates.
- **Soft Delete**: Items are marked `isDeleted: true` (Trash) before being permanently purged.

## Development Workflow

### Key Commands
- `npm run dev`: Starts the Vite dev server and launches Electron in development mode (with DevTools).
- `npm run build`: Compiles the frontend and main process for production.
- `npm run build:win`: Builds and packages the application for Windows using `electron-builder`.
- `npm install`: Installs all dependencies, including Electron binaries and media processors.

### IPC Communication
The application uses a strict `contextBridge` for security.
- **Renderer to Main**: Use `window.api.invoke(channel, ...args)`.
- **Main to Renderer**: Use `window.api.on(channel, callback)` for events like import progress.
- **Allowed Channels**: Defined in `src/preload/preload.ts`.

### Media Protocol
A custom `media://` protocol is registered in the main process to serve local files securely to the renderer, bypassing standard file system restrictions and improving performance.

## Development Conventions

1.  **TypeScript**: Always use types defined in `src/main/types.ts` for IPC and data structures.
2.  **Surgical Updates**: When modifying `LibraryManager`, ensure the `index.json` is kept in sync with individual `metadata.json` files.
3.  **Error Handling**: Wrap file system operations in try/catch blocks; the main process should gracefully handle missing files or directories.
4.  **UI Performance**: Use the `VirtualGrid` component for the gallery to handle thousands of items efficiently.
5.  **Icon Management**: Icons are located in `src/renderer/src/assets/icons/`. Prefer `.ico` for Windows builds and `.png` for others.

## Known Limitations & TODOs
- **FFmpeg/FFprobe**: Relies on `@ffmpeg-installer` and `@ffprobe-installer`. Ensure paths are correctly set in the main process.
- **Thumbnail Generation**: Heavy operations are asynchronous to prevent UI blocking, but batch imports can still be CPU intensive.
